## 6. A clarification: legacy Controlled event identity — **FAIL (HIGH)**

**Requirement (TASK-011, A post-preflight clarification):** a newly executed
`legacy` run must retain the *pre-TASK-011* Controlled event-id/timestamp
derivation. In `DelayedRecallScenario._next_event_identity`, pass the
**pre-existing two difficulty parameters** to `controlled_event_identity` when
semantics is `legacy`; include the version in the identity namespace **only**
for `entity_key_v2`; add a regression test.

**Actual behavior (verified):**
`benchmark/minemembench/scenarios/delayed_recall.py:405-407` calls
`controlled_event_identity(seed, params=self.params, phase, ordinal)`
unconditionally. Because `recall_semantics_version` was added to
`default_params` (delayed_recay.py:354), `self.params` always contains it, so
**even a legacy run hashes the version into the event id**.

Empirical proof:
```
pre-TASK-011 (2 params)  -> ctrl-6342fe1db59ccfbe969df790
current legacy (3 params) -> ctrl-3acfc1d81dca5a4e52e99dcc
actual legacy run output  -> ctrl-3acfc1d81dca5a4e52e99dcc   (matches current, NOT pre-011)
```
B's own completion note (B-COMPLETION-011.md:100-105) admits this and declares
it acceptable: *"This changes Controlled `ctrl-` event ids relative to rounds
3–4 ... — acceptable because v2 is a new treatment..."* — which is the
**opposite** of A's clarification (which requires legacy to keep the
pre-TASK-011 derivation).

Additionally, **no regression test for this property exists**: `rg` for
`controlled_event_identity|_next_event_identity|pre-TASK-011|two difficulty`
across `benchmark/tests/` returns nothing.

**Impact:** new legacy Controlled runs would produce different event ids (and
thus different metric ground-truth ids) than rounds 1–4, breaking the
"legacy is byte-for-byte unchanged / re-runnable identically" contract and the
required regression test. Timestamps are unaffected (they depend only on
phase/ordinal).

**Repair (minimal, suggested; not applied by C):**
1. In `_next_event_identity`, branch on `self._is_v2()`:
   - `legacy`: pass `{"interference_count": ..., "similar_distractor_count": ...}`
     (the two pre-existing params, version excluded) to
     `controlled_event_identity`.
   - `entity_key_v2`: pass `self.params` (version included).
   Do **not** touch `scenarios/controlled.py`.
2. Add a regression test (e.g. in `test_delayed_recall_v2.py` or
   `test_controlled_mode.py`) asserting that a Controlled `legacy` run's first
   `experience`-phase event id equals
   `controlled_event_identity(seed, {"interference_count": X,
   "similar_distractor_count": Y}, phase="experience", ordinal=0)` and differs
   from the v2 id.
